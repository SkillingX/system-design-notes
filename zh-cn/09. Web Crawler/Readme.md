# 第 9 章：设计网络爬虫

## 引言
**网络爬虫**也称为 spider 或 robot，用于发现和收集网页、图片和视频等网络内容。本章重点讨论如何设计一个可扩展的网络爬虫，用于**搜索引擎索引**。

### 网络爬虫的应用
1. **搜索引擎索引：**收集网页并创建可搜索的索引，例如 Googlebot。
2. **网页归档：**保存网络数据，以便未来查阅，例如美国国会图书馆。
3. **网络挖掘：**从网络数据中提取知识，例如分析股东报告中的财务信息。
4. **网络监控：**检测侵犯版权或商标权的内容。

### 设计挑战
优秀的爬虫需要解决以下问题：
- **可扩展性：**通过并行处理抓取数十亿个网页。
- **健壮性：**处理错误的 HTML、进程崩溃和恶意链接。
- **礼貌性：**避免用过多请求压垮目标服务器。
- **可扩展性：**只需少量改动即可支持新的内容类型。

---

## 第 1 步：理解问题

### 需求
1. 每月抓取 **10 亿个网页**（每秒 400 页，峰值 800 QPS）。
2. 只收集 **HTML 内容**。
3. 跟踪新页面和更新过的页面。
4. 忽略重复内容。
5. 将抓取数据保存 **5 年**，需要约 30 PB 存储空间。

## 第 2 步：高层设计

### 组件

1. **种子 URL：**爬虫的起点。
    - 应精心选择种子 URL，使爬虫能够沿着链接尽可能广泛地遍历网页。
    - 可以根据地域或热门网站选择，也可以根据主题选择。
    - 策略：按地域或主题（例如体育、医疗）分类。

2. **URL Frontier：**保存待下载的 URL。
   - 可以使用 **FIFO 队列**实现。

3. **HTML 下载器：**下载 URL Frontier 提供的网页。

4. **DNS 解析器：**将 URL 转换为 IP 地址。

5. **内容解析器：**验证并解析网页。
   - 丢弃格式错误的页面。

6. **内容是否已见过：**通过比较网页哈希值，检查内容是否重复。

7. **内容存储：**将 HTML 页面保存在磁盘上（热门内容可保存在内存中以降低延迟）。

8. **URL 提取器：**从已解析的网页中提取新链接。

9. **URL 过滤器：**排除黑名单 URL 或错误 URL。

10. **URL 是否已见过：**跟踪已访问的 URL，避免重复抓取。

11. **URL 存储：**保存已访问的 URL。

---

### 工作流程
1. 将**种子 URL**加入 URL Frontier。
2. **HTML 下载器**获取 URL，并通过 DNS 解析器解析其 IP 地址。
3. **内容解析器**验证内容，并将其交给“内容是否已见过”组件。
4. 如果内容是新的，使用 **URL 提取器**从中提取链接。
5. 过滤链接，将唯一的新 URL 加入 URL Frontier。

## 第 3 步：深入了解关键组件
### DFS/BFS
- 可以将 Web 看作一个有向图，其中网页是节点，超链接（URL）是边。
- 通常使用 BFS 遍历图，因为图的深度可能很大，所以 DFS 不太适合。
- 标准 BFS 不考虑 URL 的优先级，但并非每个页面的质量和重要性都相同。

### URL Frontier
- **礼貌性：**
    - 确保同一主机同一时刻只处理一个请求。在两项下载任务之间增加延迟。
    - 使用从主机名映射到队列和工作线程（下载线程）的映射。
    - 每个下载线程有独立的 FIFO 队列，并且只从该队列下载 URL。

        <img src="../../09.%20Web%20Crawler/images/politeness.png" alt="Politeness" width="500">

    - **队列路由器：**确保每个队列（b1、b2、…、bn）只包含来自同一主机的 URL。
    - **映射表：**将每台主机映射到一个队列。
    - **队列选择器：**每个工作线程对应一个 FIFO 队列，并且只从该队列下载 URL。队列选择逻辑由队列选择器负责。
    - **工作线程 1 至 N：**工作线程按顺序下载同一主机上的网页。两项下载任务之间可以增加延迟。

- **优先级：**
    - 根据 PageRank 或更新频率等指标，为重要页面分配更高优先级。

        <img src="../../09.%20Web%20Crawler/images/prioritizer.png" alt="Prioritizer" width="500">

    - **优先级计算器：**接收 URL 并计算其优先级。
    - **队列 f1 到 fn：**每个队列对应一个优先级。优先级越高，队列被选中的概率越大。
    - **队列选择器：**随机选择一个队列，但会偏向优先级较高的队列。
    - **前端队列：**负责优先级管理。
    - **后端队列：**负责礼貌性管理。

- **新鲜度：**根据页面的更新历史或重要性决定重新抓取的时间。

### HTML 下载器
- **遵守 Robots.txt：**尊重 robots.txt 文件中的规则。
- **性能优化：**
  1. 使用多台服务器分布式抓取。
  2. 使用 **DNS 缓存**避免重复查询。
  3. 在不同地理位置部署抓取服务器，以加快下载速度。
  4. 设置较短的超时时间，避免被缓慢或无响应的服务器拖住。

### 健壮性
1. **一致性哈希：**在服务器之间有效分配负载。
2. **错误处理：**避免异常导致系统崩溃。
3. **数据校验：**确保内容完整。

### 可扩展性
- 添加处理新内容类型的模块，例如 PNG 下载器、网络监控器。
- 示例：插入一个监控网络内容版权侵权的模块。

    <img src="../../09.%20Web%20Crawler/images/extensibility.png" alt="Extensibility" width="600">

### 避免有问题的内容
1. **重复内容：**使用哈希比较进行检测。
2. **蜘蛛陷阱：**使用 URL 长度上限等方式，避免无限循环。
3. **数据噪声：**过滤广告或垃圾信息等无关内容。

---

## 第 4 步：总结
### 要点
1. 网络爬虫需要在可扩展性、健壮性、礼貌性和可扩展性之间取得平衡。
2. **礼貌性**可以避免服务器过载；**优先级**可以确保先抓取重要页面。
3. 高效的存储和错误处理对于大规模抓取至关重要。

### 其他注意事项
- **服务器端渲染：**处理由 JavaScript 或 AJAX 生成的动态内容。
- **反垃圾措施：**排除低质量或无关页面。
- **数据库分片：**通过复制和分片扩展数据层。
- **横向扩展：**使用无状态服务器高效扩展抓取任务。
- **分析：**收集并分析数据，以获得有用的信息。
